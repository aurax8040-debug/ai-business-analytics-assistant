# AI 经营分析助手 PRD

版本：Public Mock Demo V1.0
状态：已实现能力的公开版产品说明
数据声明：仅使用虚构名称与脱敏 Mock Data

## 1. 产品背景

快消经营复盘通常分散在 ERP、POS、SFA、预算与供应链系统中。管理者能看到报表，但仍需人工完成口径确认、跨模块取数、原因下钻和行动跟进。单纯在 BI 上增加聊天框无法解决数据口径、权限、幻觉和结果不可追溯的问题。

本项目以“可信经营分析”为核心，将传统 BI、统一业务语义层、只读工具、Agent 编排、独立 Checker 和人工行动闭环组合成一个可运行 Demo。

## 2. 目标与非目标

### 2.1 产品目标

1. 让管理层、区域负责人和客户经理通过自然语言查询经营指标。
2. 在 ERP、POS、预算、SFA 与供应链之间保持口径隔离和来源追溯。
3. 对歧义问题先澄清，对数据不足和工具失败显式降级。
4. 只基于通过 Checker 的工具结果生成报告与图表。
5. 将建议转成需人工确认的 Demo 任务，并记录执行结果与复盘。

### 2.2 非目标

- 不自动下单、调价、改库存或写入 ERP。
- 不自动通知外部平台或真实员工。
- 不把 LLM 输出当作业务数字来源。
- 不以 Mock 结果证明真实业务增长、模型准确率或生产可用性。

## 3. 用户与核心任务

| 用户 | 核心任务 | 典型问题 |
| --- | --- | --- |
| 管理层 | 了解整体达成、利润、异常与区域差异 | “本月哪些战区需要重点关注？” |
| 区域负责人 | 下钻市场部、客户、渠道和 SKU | “战区B 10 月未达成主要来自哪里？” |
| 客户经理 | 查看客户、门店、POS 与拜访执行 | “KA系统026 的动销和拜访是否一致？” |
| 供应链角色 | 查看需求、BOM、库存与采购建议 | “SKU-001 未来两个月会卡在哪个包材？” |

## 4. 功能范围

### 4.1 BI 经营驾驶舱

- ERP Sell-in、POS Sell-out、预算、毛利、区域、客户、品类与 SKU 分析。
- 战区、市场部、渠道、客户、品类、SKU、月份筛选。
- 下钻到客户、门店或 SKU 明细，保留数据来源和口径说明。
- 无数据时显示缺失或不适用，不用 0 伪装。

### 4.2 自然语言问数与语义层

- 同义词、指标定义、维度、期间和工具路由统一维护。
- “销量”未说明时区分 ERP 出货与 POS 动销并请求澄清。
- 页面筛选可作为上下文，但用户明确输入优先。
- 连续追问继承上一轮已确认范围，切换战区时清除不相容实体。

### 4.3 Agent、Workflow 与 Checker

- Supervisor 选择直接查询或六类经营 Workflow。
- Planner 只能从已注册的只读工具中编排。
- Checker 独立复算关键指标、校验口径、权限和数据质量。
- Reporter 区分事实、推测、建议与限制；模型不可用时使用规则模板。

### 4.4 可信图表

- 图表数据只取自通过 Checker 的工具返回值。
- 自动选择趋势图或对比图，不在前端重新计算业务指标。
- 数据点携带来源、单位、口径和追问提示。
- Checker 阻断、空值或非数值不绘图。

### 4.5 行动闭环

- 用户确认建议后，必须填写负责人和截止日期才能创建任务。
- 状态流转：待处理 → 进行中 → 已完成 → 已复盘。
- 已完成必须填写执行结果，已复盘必须填写效果结论或待观察说明。
- 任务只写本地 Demo 日志，不调用外部业务系统。

### 4.6 供应链分析

- Mock 到货、质检、BOM、生产、成品库存、包材采购与追溯。
- 需求与采购建议使用确定性公式，保留参数、版本和数据质量信息。
- 水果到货与包材采购分开建模，财务结算价不在本 Demo 范围。

## 5. 数据与权限设计

- 数据源分为 ERP、POS、SFA、预算、批发和供应链，跨源指标不做无依据相加。
- Demo RBAC 由后端身份映射决定，前端自报角色不构成权限。
- 工具调用前注入有效数据范围；无法安全过滤时拒绝查询。
- 数据质量按完整性、时效性、一致性和可追溯性分级。
- 所有公开数据使用通用战区、市场部、客户、门店、员工、SKU 与供应商名称。

## 6. 异常与降级

| 情况 | 系统行为 |
| --- | --- |
| 指标口径歧义 | 请求用户选择 ERP / POS 或补充范围 |
| 无数据 | 返回空结果、覆盖边界和下一步建议 |
| 权限不足 | 在工具执行前拒绝，不返回明细证据 |
| Checker 未通过 | 不生成可信图表，不输出确定性结论 |
| LLM 未配置或失败 | 使用规则模板，保留 SQL 数字与报告结构 |
| 行动信息不完整 | 不创建任务，提示负责人/截止日期/人工确认缺失 |

## 7. 验收标准

1. 仓库在无模型密钥时可启动并完成自检。
2. 核心 BI 接口返回 Mock 标识、数据来源和口径。
3. 自然语言问数不会把 ERP 与 POS 混为同一指标。
4. Checker 阻断时图表不可用。
5. Demo 行动任务不能绕过人工确认、负责人和截止日期。
6. 公开仓库不包含真实企业、客户、门店、员工、SKU、订单、密钥、内部 URL 或本机绝对路径。
7. Git 历史从公开版首个脱敏提交开始，不继承私有仓库历史。

## 8. 后续规划

- 接入可配置的指标语义目录与评估集。
- 增加生产级 SSO/RBAC、审计日志和数据契约。

- 在获得明确授权后再接真实数据沙箱或外部任务系统。
